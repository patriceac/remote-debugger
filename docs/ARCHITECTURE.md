# Architecture and trust model

`RemoteDebugger.Core` contains bounded framing, pairing cryptography, session timing, path confinement, coordinate mapping, typed sorting, and update policy. `RemoteDebugger` contains the WinForms interface, controller CLI, interactive agent, local privileged broker, update transport, and Windows operations. `RemoteDebugger.Lab` is isolated acceptance tooling excluded from distribution.

## Identity and access

The visible agent listens on IPv4 TCP 45832 and answers discovery on UDP 45833. The Private-profile firewall rules are restricted to LocalSubnet. Discovery is an untrusted hint. Pairing uses J-PAKE with the Bouncy Castle NIST 3072-bit group, mutual key confirmation, and a six-digit temporary secret. The derived authentication key binds the TLS certificate and controller executable hash. Codes rotate every five minutes, preserve leading zeroes, and are consumed on successful pairing. Per-code and rolling rate limits constrain online guessing across rotations. Codes are never sent as ordinary RPC credentials.

TLS 1.2/1.3 protects transport. Subsequent RPCs and streams pin the code-authenticated certificate. Schannel uses a user key container; durable key material and the controller connection profile use DPAPI CurrentUser. The agent retains a hash of the controller grant. Normal launches require new pairing. A paired operator has the remote user's interactive access plus the explicitly provisioned maintenance capabilities; this is not a sandbox against that operator.

Internet mode wraps that same endpoint TLS stream in outbound WSS connections to a private Cloudflare Worker for discovery, pairing and fallback relay. A 64-bit random support ID identifies one SQLite-backed Durable Object; its independently generated owner key prevents another hosting user from registering as that agent. A private hosting key restricts relay use but does not grant endpoint access. After pairing, the controller requests authenticated direct candidates from the agent and probes them with the existing certificate pin and session token. Ordinary controller requests open short-lived channels, while live input and an update transfer keep dedicated authenticated channels open and send ordered framed requests over them. The agent joins each relay channel through its existing outbound control connection. Endpoint J-PAKE, certificate pinning, executable matching, operation limits and revocation apply to both transports. Cloudflare receives encrypted records, never desktop or file plaintext. The displayed public IP is a post-pair direct candidate; if it is unreachable, the saved relay route remains available.

WebSocket hibernation preserves channel routing without a constantly running process. Session metadata and an owner-key hash survive hibernation; payloads are not stored. Re-registration replaces the previous connection generation. Pending channels expire and inactive objects delete their state. Settings, owner keys and saved controller connections are protected by DPAPI. See [internet setup and limits](INTERNET.md).

## Session lifetime

One logical session spans independent RPC sockets and rolling screen streams. Heartbeats run every five seconds; fifteen seconds without activity detects loss. A monotonic ten-minute grace then allows reconnection before the session ends. Stream acknowledgements also prove activity. Termination releases input, cancels normal work and any armed update, ends the maintenance lease, and revokes the agent grant. The unauthorized idle listener remains available to report access denial to the controller. A separate monotonic ten-minute application-exit countdown starts on the agent after termination and continues while hidden in the tray. Starting new assistance cancels it and replaces the idle server; repeated termination events do not extend the deadline. The controller remains open. The power request begins only after an authenticated, binary-matched support session is established; it lasts through support and reconnect grace, without changing saved power settings. An unpaired or synchronizing listener can sleep normally.

Each native table stores completed header resize/reorder gestures in its own JSON file below the user data root's `tables` directory. Stable column IDs decouple saved order from source order, and widths use 96-DPI logical pixels. Native handle recreation and DPI changes reapply preferences without recording those programmatic changes as user input. Missing/corrupt preferences fall back to defaults; new columns are appended and removed columns ignored.

Either window can hide to the tray while its session continues and restore from its notification icon. A new session requires a new agent code. Neither role is registered to start with Windows. The local broker starts on demand and becomes dormant when its work is finished.

## Privilege and executable synchronization

One authorized administrator installation creates protected Program Files application and service paths, protected ProgramData configuration, an exact publisher certificate pin, and a registered Windows SID. The visible agent stays in the interactive user's session. The LocalSystem broker has no TCP or UDP listener and accepts bounded named-pipe operations only after caller identity verification. The agent verifies the broker's actual pipe PID against Service Control Manager and its protected executable identity.

After pairing, administrator maintenance opens automatically and lasts for the support session. Its commands retain individual timeouts and cancellation. The old one-hour helper and per-command elevation prompts are replaced by the broker. Windows consent is still required for initial provisioning; the application does not bypass UAC or automate secure-desktop approval.

The controller's running executable SHA-256 is authoritative. The agent must match its exact signed bytes, even for a downgrade or a different build with the same version. Updates transfer in resumable 512 KiB chunks over one authenticated channel with a per-chunk acknowledgement, validate the entire file and pinned Authenticode publisher, stage in protected storage, and use the broker for replacement. The old executable is recoverable until startup and remote health are confirmed. Mismatch blocks ordinary support operations and live input.

A planned restart uses a DPAPI-protected, bounded reconnect grant tied to the paired session and permitted executable hashes. Successful confirmation deletes it. An ordinary launch cannot use it. Manual termination cancels replacement and prevents a later update-driven relaunch. See [installation and signing](INSTALLATION.md) for publisher enrollment and release tooling.

## Commands, files, and desktop

RPCs have UUIDs and bounded execution budgets. Commands use an executable and argument array; shell interpretation is explicit. Output is bounded and drained. Cancellation kills command process trees. Interactive applications launched for diagnosis can outlive the controller. A per-process cache retains up to 2,048 consequential mutation replies; the same UUID and arguments return the original result, conflicting reuse fails. After an agent restart, inspect state before retrying an uncertain mutation.

Workspace uploads use resumable 256 KiB chunks and final SHA-256 verification. Path traversal, alternate data streams, and reparse traversal are rejected. Uploads support up to 16 GiB. Downloads verify a temporary local file before promotion.

Desktop transport negotiates H.264 over pinned TLS for the interactive viewer, using libx264's low-latency/no-B-frame configuration, and falls back to binary JPEG in the same session when the runtime is unavailable or measured encoding remains over budget. Both modes use a five-fps target and one receipt-acknowledged frame in flight. Capture starts after the previous receipt, so the sender never queues old captures. The controller decodes every H.264 packet in order, then retains only the newest decoded frame when the presenter is slow; it never drops encoded dependency frames. It takes that frame after resuming on the UI thread, so blocked UI callbacks do not retain stale images. Cancellation discards pending frames and stops the receiver. The interface reports actual presentation cadence and the active codec, and marks the image live only while fresh frames are presented. Monitor geometry and layout identifiers bind pointer coordinates to the displayed desktop; stale geometry is rejected. Focus loss, interruption, pause, and termination release input. A watchdog also releases stuck input. Secure desktop and locked-session input remain unavailable.

Native debugging uses the Windows debugging APIs and records actual attach, breakpoint, event, and detach outcomes. Minidumps use MiniDumpWriteDump. Intervention history records operation metadata without pairing codes, keystrokes, images, or command arguments.
